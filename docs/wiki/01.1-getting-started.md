# 1.1 Primeros pasos

Guía para instalar y ejecutar PascualBet en un entorno local.

Páginas relacionadas: [Visión general](01-overview.md) · [Frontend](02-frontend.md) · [Backend](04-backend.md)

## Requisitos

| Requisito | Versión / detalle |
|-----------|-------------------|
| Node.js | v18 o superior (según `README.md`). Vite 7 (`front/package.json`) requiere Node 20.19+ o 22.12+, por lo que se recomienda Node 20 LTS o 22 LTS. |
| npm | Incluido con Node.js. Cada subproyecto tiene su propio `package-lock.json`. |
| Supabase | Un proyecto Supabase con las tablas y los procedimientos almacenados que usa el backend (ver [Backend → Procedimientos almacenados](04-backend.md#procedimientos-almacenados)). |

> El repositorio **no** incluye los scripts SQL de las tablas ni de los procedimientos almacenados; deben existir previamente en el proyecto Supabase.

## Instalación

El repositorio contiene dos proyectos independientes: `front/` y `server/`. Se instalan y ejecutan por separado.

### Backend (`server/`)

```bash
cd server
npm install
# crear server/.env (ver sección "Variables de entorno")
npm run start:dev
```

El servidor escucha en `http://localhost:3000` por defecto (`server/src/main.ts`).

### Frontend (`front/`)

```bash
cd front
npm install
npm run dev
```

Vite sirve la aplicación en `http://localhost:5173`.

## Variables de entorno

Solo el backend usa variables de entorno. Se cargan con `dotenv` en `server/src/db/supa.client.ts` desde un archivo `server/.env` (ignorado por git en `server/.gitignore`).

| Variable | Obligatoria | Uso | Archivo |
|----------|-------------|-----|---------|
| `SUPABASE_URL` | Sí | URL del proyecto Supabase. Si falta, el servidor lanza `Missing SUPABASE_URL or SUPABASE_KEY environment variables` al arrancar. | `server/src/db/supa.client.ts` |
| `SUPABASE_KEY` | Sí | Clave de API de Supabase usada por `createClient`. | `server/src/db/supa.client.ts` |
| `PORT` | No (por defecto `3000`) | Puerto HTTP de NestJS. | `server/src/main.ts` |
| `CORS_ORIGIN` | No (por defecto `*`) | Origen permitido por CORS. Conviene restringirlo en producción (p. ej. `http://localhost:5173`). | `server/src/main.ts` |

Ejemplo de `server/.env`:

```env
PORT=3000
SUPABASE_URL=https://<tu-proyecto>.supabase.co
SUPABASE_KEY=<tu-clave>
CORS_ORIGIN=http://localhost:5173
```

### Apuntar el frontend a un backend local

El frontend no lee variables de entorno: la URL de la API (`https://pascualbet-cvr6.vercel.app`) está escrita directamente en:

- `front/src/utils/betApi.js` — `registerBet` (`/api/apuestas/new/bet`) y `registerTransfer` (`/api/apuestas/new`).
- `front/src/store/balance.js` — `syncBalance` (`/api/users/find/:uid`).
- `front/src/components/login.vue` — `handleLogin` (`/api/users/login`) y `handleSignup` (`/api/users/new`).

Para desarrollo local contra `http://localhost:3000` hay que sustituir esa URL en los tres archivos.

## Scripts de `package.json`

### `front/package.json`

| Script | Comando | Descripción |
|--------|---------|-------------|
| `dev` | `vite` | Servidor de desarrollo con recarga en caliente (puerto 5173). |
| `build` | `vite build` | Compila la aplicación a `front/dist/` (configurado en `front/vite.config.js`). |
| `preview` | `vite preview` | Sirve localmente el resultado de `build`. |

Dependencias principales: `vue`, `vue-router`, `tone`. Dependencias de desarrollo: `vite`, `@vitejs/plugin-vue`, `tailwindcss`.

### `server/package.json`

| Script | Comando | Descripción |
|--------|---------|-------------|
| `build` | `nest build` | Compila TypeScript a `server/dist/`. |
| `format` | `prettier --write "src/**/*.ts" "test/**/*.ts"` | Formatea el código con Prettier (`server/.prettierrc`). |
| `start` | `nest start` | Arranca el servidor. |
| `start:dev` | `nest start --watch` | Arranca en modo desarrollo con recarga. |
| `start:debug` | `nest start --debug --watch` | Modo depuración con recarga. |
| `start:prod` | `node dist/main` | Ejecuta la versión compilada. |
| `lint` | `eslint "{src,apps,libs,test}/**/*.ts" --fix` | Lint con ESLint (`server/eslint.config.mjs`). |
| `test` | `jest` | Pruebas unitarias (`*.spec.ts` dentro de `src/`). |
| `test:watch` | `jest --watch` | Pruebas en modo observación. |
| `test:cov` | `jest --coverage` | Cobertura en `server/coverage/`. |
| `test:debug` | `node --inspect-brk ... jest --runInBand` | Depuración de pruebas. |
| `test:e2e` | `jest --config ./test/jest-e2e.json` | Pruebas end-to-end (`server/test/*.e2e-spec.ts`). |

Dependencias principales: `@nestjs/common`, `@nestjs/core`, `@nestjs/platform-express`, `@nestjs/throttler`, `@supabase/supabase-js`, `bcryptjs`, `cors`, `dotenv`, `helmet`, `rxjs`.

> En la raíz solo existe un `package-lock.json` sin `package.json`; todo el trabajo se hace dentro de `front/` y `server/`.

## Verificación rápida

1. Abrir `http://localhost:5173` → debe mostrarse la pantalla de login (`front/src/components/login.vue`).
2. Crear una cuenta (mayor de 18 años, contraseña de 12–24 caracteres alfanuméricos con al menos un número y una mayúscula).
3. Iniciar sesión → redirige a `/menu`.
4. En DevTools → Network, jugar una partida y comprobar el `POST /api/apuestas/new/bet` con los headers `x-user-id` y `x-session-token` (procedimiento descrito en `IMPLEMENTACION_COMPLETA.md`).
